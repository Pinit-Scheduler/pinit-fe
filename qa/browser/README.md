# Candidate UI through the real production API

This trusted-branch-only workflow builds the exact FE PR head and serves **only its genuine dist documents/static files** at the canonical frontend browser origin. Requests to the production backend are native HTTPS and are never intercepted or fulfilled. Two independent Chromium BrowserContexts use their own normal fixture login, cookies and storage. Existing user browser profiles are never opened.

Before any write, the harness requires the root-approved BE release hash, the exact same-repository PR branch/head, public readiness UP, all four OAuth metadata scopes, and the workspace OpenAPI paths. A worker-local exclusive marker prevents a restarted worker from creating another pair. There are exactly two signup attempts maximum, no signup retry, one browser worker, zero test retries, and a bounded run. This workflow must be pushed only after the orchestrator has independently verified that exact BE release in production; the public health response itself does not advertise a source hash.

Serial scenarios share the two accounts while independently reporting UI login/cookie isolation, personal-space invitation prohibition, space/project CRUD, joining/reusing/revoking an invitation, signup nicknames and administrator capabilities, creator/default versus explicit-null assignees, all-spaces Today and due/ready overlap, Task and Schedule stale-draft/SSE/409/one-acknowledgement behavior, common linked state, suspended capabilities, running atomic moves/dependency detachment and both old-client resource evictions, project child moves, task/schedule and project/space trash/restore, purpose-only clearing, delegation/member removal, real three-scope/four-scope OAuth consent, and 390×400 mobile/keyboard/error focus/dark screenshots.

Only explicitly tracked fixture resource IDs are archived with freshly read versions; only owned invitation/grant IDs are revoked. The fixture accounts and public OAuth client registration remain, and their counts are reported. No permanent purge, broad trash empty, broad grant revoke, other user's data, production SQL/Redis mutation, policy bypass or clock manipulation is used.

Limits are explicit: this transport proves candidate bundle → real API → database behavior, **not canonical CDN or production service-worker delivery**. Service workers are blocked for this candidate check; canonical assets/cache v26 require a separate read-only postdeploy check. One-hour natural invitation expiry and a historical mismatched-project Task/Schedule pair cannot be fabricated through current production APIs; real BE Redis-TTL and historical-migration integration coverage are separate evidence. Repeated acceptance by the second fixture checks idempotence, while genuinely concurrent distinct new-member acceptance remains BE integration coverage. No successful browser result is recorded before the entire job passes.

The root application dependencies remain unchanged. The isolated QA package locks official Playwright 1.65.0. The standard public GitHub runner uses no artifact upload, dependency cache or paid service. The safe reporter drops raw exceptions, console/stderr, arbitrary worker output, request/response bodies, URLs, credentials, trace, HAR, cookies and storage state. After a completely successful suite it exports only 2–3 guarded/masked final-space JPEGs (≤80 KiB each, bounded base64 chunks and SHA256). Images are evidence for human review, not an automated claim about contrast quality.
