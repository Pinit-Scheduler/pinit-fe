# 워크스페이스 UI 구현·배포 기준

핀잇 디자인 시안을 실제 FE로 옮기는 변경이다. 기존 인증·API·반복·계획·통계 처리는 유지하고, 카테고리만 회원 소유의 별도 저장 계약을 추가한다. 이 문서는 2026-11-03 확정한 설계와 배포 순서를 기록한다.

## 확정 설계 12개

| 항목 | 기준 |
| --- | --- |
| 1. 분류 | 화면에는 단일 카테고리만 표시한다. 기존 다중 태그는 원본 데이터로 유지하며 수정 요청에서 지우지 않는다. 기본 카테고리 6개와 사용자 카테고리를 제공한다. |
| 2. 기존 데이터 | 기존 작업·일정·반복 시리즈의 카테고리는 모두 **없음**이다. 이름·태그로 분류를 추측하거나 자동 변환하지 않는다. |
| 3. 작업과 일정 | 작업을 일정으로 생성할 때 서버가 작업 카테고리를 한 번 복사한다. 이후 두 카테고리는 독립적으로 수정된다. |
| 4. 작업 맵 | 전체 미완료 작업을 기본으로 보여 주며 완료 표시를 켤 수 있다. 완료한 선행 작업은 연결 맥락에 남긴다. 시작 가능 여부는 서버가 정한 상태를 따른다. |
| 5. 통계 | 완료 일정의 **실제 실행 시간**을 주 지표로 쓴다. 계획 시간은 별도 지표로 구분한다. |
| 6. 예상 시간 | 난이도 기준과 직접 입력을 명시적으로 선택한다. 기록 기반 보정은 플래너 옵션이며 기본값은 꺼짐이다. 켰을 때 기존 BE의 최근 90일·최소 5개 기록 기준을 따른다. |
| 7. 반복 수정·삭제 | 이번만(THIS)을 기본으로 한다. 이번 및 이후(FOLLOWING)·전체(ALL)는 같은 대화상자에서 영향 미리보기를 본 뒤 한 번 확인한다. |
| 8. 하루 계획 | 별도 페이지에서 미리보기 → 조정 → 선택 항목 적용 순서로 진행한다. 실패하면 입력과 선택을 유지한다. |
| 9. 일정 이동 | 선택한 일정만 이동한다. 다른 일정과 시각을 맞바꾸지 않는다. |
| 10. 모바일 입력 | 입력 중에는 하단 메뉴와 플레이어를 숨기고 저장·취소 버튼을 고정한다. 진행 중인 일정의 시간은 계속 흐른다. |
| 11. 피드백·동시성 | 성공 안내는 짧게, 오류는 재시도할 수 있도록 지속 표시한다. 일정 상태 변경은 공통 진행 잠금으로 중복 실행을 막고, 다른 기기의 변경도 다시 조회한다. |
| 12. 상세·입력 화면 | 데스크톱은 모달, 모바일은 전체 화면을 쓴다. 실제 URL·뒤로가기·목록 맥락을 유지하고, 미저장 변경 이탈 경고와 직접 링크의 복귀 경로를 제공한다. |

난이도 기준 예상 시간은 1→15분, 2→30분, 3→45분, 5→60분, 8→90분, 13→120분, 21→180분이다. 입력하지 않은 값을 직접 입력값으로 저장하지 않는다. 예상 시간 수정 요청에서 필드 생략은 유지, `PT0S`는 직접 입력 해제라는 기존 계약을 보존한다.

- 레이아웃 개편으로 스크롤 영역이 바깥으로 이동한 점을 반영해, 당겨서 새로고침도 실제 스크롤 영역의 맨 위에서만 동작한다.

## 카테고리 sidecar API

기존 Task·Schedule DTO와 태그 저장소를 대체하지 않는다. FE는 기존 인증 클라이언트로 `/v2/categories`에 접근하고, 서버가 인증된 회원의 항목과 카테고리 소유권을 검사한다. 클라이언트가 보낸 회원 ID로 분류 소유자를 정하지 않는다.

| 메서드·경로 | 본문·결과 |
| --- | --- |
| `GET /v2/categories` | `{ categories, taskAssignments, scheduleAssignments, seriesAssignments }` |
| `POST /v2/categories` | `{ name }` → 생성한 `{ id, name, builtIn: false }` (201) |
| `PATCH /v2/categories/{id}` | `{ name }` → 변경한 카테고리 |
| `DELETE /v2/categories/{id}` | 사용자 카테고리와 해당 회원의 연결을 제거한다 (204). 작업·일정은 삭제하지 않는다. |
| `PUT /v2/categories/tasks/{id}` | `{ categoryId: number 또는 null }` (204) |
| `PUT /v2/categories/schedules/{id}` | `{ categoryId: number 또는 null }` (204) |
| `PUT /v2/categories/recurrences/{id}` | `{ categoryId, scope, fromDate? }` (204) |

- 기본 카테고리 ID는 `-1` 업무·커리어, `-2` 학습, `-3` 개인 프로젝트, `-4` 생활·행정, `-5` 건강·운동, `-6` 여가·관계다. 기본 정의는 변경·삭제할 수 없다. 사용자 카테고리는 양수 ID를 쓴다.
- 연결 맵은 항목 ID를 키로 갖는다. 키가 없거나 명시적으로 `null`을 저장하면 **없음**이다. 이름은 앞뒤 공백을 제거한 1~30자이며 같은 회원 안에서 대소문자를 무시하고 중복을 막는다.
- 반복 카테고리의 `TEMPLATE`는 앞으로 생성할 회차의 기본값만, `ALL`은 기존 회차와 템플릿을, `FOLLOWING`은 원래 회차 날짜인 `fromDate` 이후와 템플릿을 변경한다. 개별 회차를 따로 고친 뒤에는 이후 생성이 그 회차를 덮어쓰지 않는다. 시리즈를 나눌 때 템플릿을 이어받는다.
- 삭제되거나 다른 회원 소유인 항목에는 연결할 수 없다. 조회는 활성 상태인 같은 회원의 항목만 반환한다. 휴지통에서는 연결 원본을 보존하여 복원 시 되살리고, 회원 탈퇴에서는 이름과 연결을 함께 지운다.
- 목록·맵에서 첫 페이지만 분류해 전체 결과처럼 표시하지 않는다. 카테고리 필터는 조회 대상 전체를 확인한 뒤 적용한다. 분류 캐시는 작업·일정 변경과 화면 복귀 시 갱신하고 계정 변경 시 분리한다.

작업·일정 생성과 카테고리 저장은 별도 HTTP 요청이다. 분류 저장만 실패했을 때는 생성된 항목 ID를 유지하고 분류 저장을 재시도한다. 재시도 때문에 같은 항목을 다시 생성하지 않는다.

## 마이그레이션과 배포 순서

**BE를 먼저 배포해야 한다.** 기존 서버에는 카테고리 API가 없으므로 FE만 먼저 배포하면 분류 조회·저장이 실패한다.

1. BE 브랜치의 `V2_0016__workspace_categories.sql`을 포함해 사전 배포 환경에서 Flyway·스키마 검증을 수행한다.
2. BE를 배포하고 실제 인증으로 카테고리 조회·사용자 카테고리 CRUD·없음 저장·소유권 거부·작업→일정 복사를 확인한다.
3. FE를 배포한다. `VITE_USE_MOCK_API=true`로 검증한 화면과 실제 API를 연결한 화면을 구분하고, 운영 빌드가 실제 API 주소를 쓰는지 확인한다.
4. 반복 회차 생성·시리즈 분리·플래너 적용 경로에서도 서버 분류 복사가 적용되는지 확인한다.
5. 회귀가 생기면 FE부터 이전 버전으로 되돌린다. 추가 테이블은 유지한다. 롤백을 위해 분류 데이터나 기존 태그를 삭제하지 않는다.

`V2_0016`은 사용자 카테고리용 `workspace_category`, 연결용 `workspace_category_assignment`, ID 생성기 테이블을 추가한다. 기존 Task·Schedule·태그 행을 수정하거나 분류 연결을 생성하지 않는 추가형 마이그레이션이다.

## 검증 범위와 실환경 확인

로컬 mock 브라우저 QA는 화면 배치·입력·URL 복귀·분류 표시·오류 상태를 확인한다. mock이 성공해도 실제 인증·네트워크 지연·동시 수정·MySQL 마이그레이션이 검증된 것은 아니다.

BE 통합 테스트는 H2 MySQL 모드의 실제 Spring 서비스·저장소·HTTP 컨트롤러를 사용한다. 카테고리 소유권, 원본 태그 보존, 없음 저장, 독립 복사, 실제 반복 회차 생성, 시리즈 분리, 휴지통 항목 거부, 탈퇴 삭제문과 마이그레이션 문법을 확인한다. 실제 MySQL·인증 게이트웨이·브라우저와 조합한 운영 검증을 대신하지 않는다.

배포 전 확인할 항목:

- 실제 MySQL에 적용·기존 데이터 유지·동시 생성 시 이름 중복 처리·회원 탈퇴 정리.
- 서로 다른 계정 및 기기의 분류 변경, 로그아웃 중 늦게 도착한 응답, 일정 시작·완료·취소 실패 후 재시도.
- 카테고리 저장 단계만 실패한 생성 요청과 반복 시리즈 생성의 중복 방지.
- DST·회원 시간대·자정 경계, 원래 회차 날짜와 이동한 표시 날짜, 여러 페이지에 걸친 선행 작업.
- iOS/Android PWA, 가상 키보드·안전 영역·뒤로가기, 다크모드, 키보드와 스크린 리더, 긴 제목·많은 작업.
- 실제 실행 시간 통계와 계획 시간의 일치 여부, 기록 보정 옵션, 플래너 충돌 시 입력 유지.
