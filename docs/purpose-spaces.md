# 목적 스페이스·프로젝트 프론트엔드

스페이스 전환과 관리 화면은 `/app/spaces`, 초대 수락은 `/spaces/join/:token`이다. 공개 초대 주소로 진입하면 기존 로그인·회원가입 복귀 경로를 이용한다. 이름은 서버가 반환한 회원 닉네임만 표시한다.

## 원본과 책임

- 승인 UI: `Pinit-Scheduler/pinit-ui-design@97f5a9d`, 최신 설계 문서: `5ac921f9`의 `docs/design-evidence/team-space-policy.md`, `backend-domain-boundary.md`.
- 이후 확정된 정책: 관리자만 초대·참여자 관리, 한 시간 내 여러 사람이 사용하는 링크, 작업·연결 일정 동반 이동, 공유 실행 상태, 스페이스를 넘는 이동의 선후관계 해제·기록, 미담당 작업의 오늘 제외.
- 실제 업무 규칙, 기본 담당자, 권한과 상태별 가능한 행동은 서버 응답이 원본이다. FE는 `allowedActions`, 버전, 결과를 소비하며 로컬 공유 작업 복제나 모의 권한 엔진을 만들지 않는다.

## 데이터 연결

`src/features/spaces`는 스페이스 목록·프로젝트·참여자 스냅샷, 전환, 관리 화면, 초대, 소속·담당자 입력과 실시간 무효화를 담당한다. 개인 기본 스페이스의 음수 ID를 보존한다. 숫자 0을 null로 묵시 변환해 기본 스페이스로 우회하지 않으며 식별자 유효성은 서버가 검사한다. 현재 서버 계약에서 0은 유효한 스페이스 ID가 아니다. 선택 스페이스는 계정별 세션 저장소의 보기 설정이다.

작업·일정·반복 API는 `/v2/workspace/tasks`, `/schedules`, `/recurrences`의 wrapper를 기존 화면 타입으로 변환한다. 내용과 `location`·`assignee`를 한 번에 저장한다. 반복의 `ALL`·`FOLLOWING` 범위와 영향 미리보기는 유지한다. 내부 `categories` 이름은 기존 컴포넌트 호환을 위해 남지만 `/v2/projects/snapshot`의 실제 프로젝트 ID를 사용한다.

새 작업의 담당자 생략과 `{assignee:{memberId:null}}`은 다르다. 생성 기본값은 서버 draft를 읽으며, 기존 미담당 작업을 편집할 때 null을 본인으로 대체하지 않는다. 오늘은 선택 스페이스와 독립된 `mine=true` 조회를 사용한다. 시작 가능한 작업과 오늘 마감 작업은 따로 조회하므로 두 영역에 같은 작업이 나타나는 교집합을 유지한다.

## 편집·실시간·실패

폼은 처음 읽은 `expectedVersion`과 반복의 `recurrenceVersion`을 보존한다. SSE나 후속 GET이 캐시를 갱신해도 편집 초안의 버전을 바꾸지 않는다. 서버 `VERSION_CONFLICT`는 저장 실패이며 한 번 확인하면 최신 화면을 읽는다. 자동 재저장·자동 덮어쓰기는 하지 않는다. 계획 제안의 `blocks[].expectedVersion`도 로컬 편집에서 보존해 승인 요청에 그대로 보낸다.

일정 편집은 일반 상세 화면의 실시간 재조회와 분리해 최초 snapshot을 유지한다. 리소스 제거 알림에는 입력을 바꾸지 않는 접근 재검증만 하고, 서버가 403/404/410을 확정하면 편집을 종료한다. 일시 조회 실패는 초안을 없애지 않는다. 일정 상태 저장은 서버 wrapper를 버전 검사하는 캐시에 한 번 반영하며 별도 버전 없는 상태 덮기를 하지 않는다.

SSE는 `/v2/workspace/events` 단일 Bearer fetch stream이다. 스페이스 수가 늘어도 브라우저 HTTP/1 연결을 스페이스마다 점유하지 않고 `changed.spaceId`로 구분한다. 구독 수명 안에서 마지막 SSE id를 기억해 재연결의 `Last-Event-ID`로 보내며 계정 변경 시 폐기한다. 토큰 갱신·계정 변경·권한 박탈을 처리하고 연결 복구 시 목록을 다시 읽는다. 늦게 도착한 이전 버전이 최신 캐시 버전을 낮추지 않는다. 편집 입력은 그대로 남는다. 공유 일정 상태 변경 뒤 연결 작업에 대한 추가 쓰기는 하지 않고 서버 처리 결과를 다시 읽는다.

작업·일정의 `MOVED_OUT`·`DELETED`·`PURGED`는 기존 스페이스에 계속 참여하고 있어도 해당 리소스의 메타데이터와 캐시를 제거한다. 작업에 연결된 일정과 실행 중 표시도 함께 정리한다. 상세 조회의 403/404/410은 같은 방식으로 처리하며 네트워크·503 오류만으로 캐시를 지우지 않는다. 요청 시작 시 읽은 무효화 revision을 비교하므로 이동 전에 시작된 상세·목록 응답은 리소스를 되살리지 못한다. 이후 새 요청으로 접근이 확인되면 같은 엔티티 버전도 다시 표시할 수 있다.

초대 수락과 폼 제출은 같은 렌더 사이의 연속 클릭도 잠근다. 서버가 참여 완료를 반환한 뒤 스페이스 재조회가 실패해도 수락을 다시 POST하지 않는다. 만료·철회·삭제된 스페이스·저장 실패는 서버 응답을 표시한다. 초대 토큰과 응답은 HTTP 디버그 로그에서 제외한다.

응답 body를 읽은 뒤에도 현재 계정과 요청 revision을 검사해 이전 계정의 늦은 응답을 차단한다. 정상 동일 계정 토큰 갱신은 유지한다. 상세 재조회 실패 중에도 일정 배정은 캡처한 작업 ID·버전으로 요청하며, 버전이 없으면 오류와 입력을 유지한다.

로그인·가입·갱신·소셜 콜백과 OAuth 토큰·등록·철회·동의 응답도 정확한 인증 경로에서 기본으로 로그를 가린다. 개별 호출의 `sensitiveRequest`·`sensitiveResponse`는 계속 사용할 수 있다. 인증 비밀값이 요청 URL·본문·성공 응답·오류 로그에 남지 않도록 하며 정상 API 응답과 오류 처리는 유지한다.

휴지통은 서버에서 관리자 권한으로 필터한 `/v2/trash` 목록을 사용한다. 공유 복구·영구 삭제는 목록의 버전을 새 workspace 경로에 보낸다. 되돌리기는 삭제된 행의 최신 버전을 조회한 뒤 수행하며 버전 없는 legacy 쓰기로 우회하지 않는다. 전체 비우기는 기존 개인 휴지통만 대상으로 한다. 서버가 복구 결과를 제공하면 실제 미복구 선후관계 수를 표시한다.


이번 변경의 `src/shared/api/config.ts`는 개발에서도 `VITE_API_BASE_URL`을 읽도록 확장했다. 준비 baseline에서는 task API의 개발 origin이 `http://localhost:8080`으로 고정됐고 이 변수가 운영 빌드에만 반영됐으므로 그 동작과 구분한다. 현재 개발 기본값은 API `http://localhost:8080`, auth `http://localhost:8081`, notification `http://localhost:8082`다. 통합 검증에서는 `VITE_API_BASE_URL`, `VITE_AUTH_BASE_URL`, `VITE_NOTIFICATION_API_BASE_URL` 세 변수를 모두 `http://localhost:8080`으로 지정한다. URL helper가 API 버전 경로를 붙이므로 환경 변수에는 `/v2`나 `/v0`를 넣지 않는다. 운영 데이터베이스나 운영 API로 개발 검증하지 않는다.

`tests/workspace-spaces.test.mjs`는 wrapper, 권한·버전 전달, null/생략, 오늘 범위, 초대 오류·중복, SSE 인증/권한/계정, 충돌·로그 비밀값, 늦은 스냅샷과 휴지통을 검증한다. 기존 편집 수명주기 테스트는 원자 저장 계약에 맞춰 내용+프로젝트 실패 시 초안 유지, 성공 후 재조회 실패와 재쓰기 금지 경계를 유지한다. 브라우저 통합과 배포 후 검사는 단위 검사와 별도로 수행한다.

## 오늘 남은 일정 재배치와 스페이스 범위

새 [재배치 패널](day-replanning.md)은 현재 접근 가능한 스페이스·프로젝트를 명시적으로 요청하고 본인 담당 Task와 Schedule만 이동 후보로 삼는다. 다른 스페이스는 결과에 포함하지 않고, 같은 스페이스의 다른 담당자·미담당·다른 프로젝트 일정은 고정 장애물로 둔다. 스페이스·프로젝트·참여자 변경과 접근/리소스 제거 시 미리보기의 복사본도 버리며 지연 응답의 actor·scope·resource revision을 검사한다. 브라우저 검증은 폐기 가능한 로컬 Task/H2 fixture만 사용하며, master에서 제거한 운영 쓰기 QA를 다시 추가하지 않는다.

## AI 앱 동의

MCP는 기존 `mcp:read`·`mcp:write`·`mcp:delete`를 개인·공유 스페이스 도구에 동일하게 적용한다. 별도 스페이스 권한이나 재동의는 필요하지 않으며, 기존 연결도 동작별 권한으로 스페이스 도구를 사용한다. 스페이스 참여·관리자 역할·버전과 미리보기·확인은 서버가 계속 검사한다. 삭제·참여자 제외·탈퇴·초대 철회에는 `mcp:delete`와 미리보기·확인이 필요하다. 과거 추가 scope 문자열은 BE가 no-op으로 호환 처리하고 새 동의 응답에는 세 동작 권한만 제공한다. FE는 이 계약을 소비하며 별도 스페이스 권한 타입·분기를 두지 않는다.

## 스페이스 화면 개편 A단계 (2026-11-09)

화면 쪽(FE)만으로 할 수 있는 변경이다. 승인된 설계 근거는 `Pinit-Scheduler/pinit-ui-design`의 `docs/design-evidence/spaces-hub.md`(cd62239)이고 계획은 pinit-docs PR #11이다. 아래는 이 브랜치(`codex/spaces-phase-a`)의 코드가 하는 일이며, 설계 의도와 확인하지 못한 것은 따로 표시한다.

### 구현한 것

- 용어: UI의 "공간"을 "스페이스"로 바꿨다(조사 포함, 예: 스페이스로·스페이스를). "저장 공간"과 "여유 공간"은 일반 단어라 유지한다. `tests/space-terminology.test.mjs`가 `src`의 `.ts`·`.tsx`·`.css`에 남은 "공간"을 검사한다. 조사가 맞는지까지 검사하지는 않는다.
- 범위 규칙: `src/features/spaces/scope.ts`가 화면별 범위를 정한다. `tests/space-scope.test.mjs`가 검증한다.
  - `routeScope`: `/app/tasks`·`/app/schedules`·`/app/task-map`은 `selected`, `/app/deadline-risk`는 `personal`, 그 밖은 `all`.
  - `projectSelectionTarget`: `selected` 화면이면 이동 없음(`null`), 아니면 `/app/tasks`.
  - `createSpaceIdFor`, `scopeCrumb`, `scheduleMineParam`, `audienceFor`, `audienceSchedules`(아래에서 설명).
- 브레드크럼(`TopBar`, `AppShell`): 목록 화면은 "스페이스 › 프로젝트", 오늘·통계·휴지통 등은 "모든 스페이스", 마감 위험은 개인 스페이스 이름. 선택된 스페이스가 아직 없으면(불러오는 중) "스페이스"라고만 쓴다.
- 화면 유지 전환(`SpaceChrome.tsx`): 스페이스를 바꿔도 현재 화면에서 이동하지 않는다. 프로젝트를 고르면 작업·일정·작업 맵 목록에서는 그 화면에 머물고, 그 밖(상세·폼 포함)에서는 작업 목록으로 간다.
- 일정의 내 일정/팀 전체(`SchedulesTabPage`, `useScheduleAudience`, `ScheduleCard`):
  - 개인 스페이스가 아니고 참여자가 2명 이상인 스페이스에서만 전환을 보인다. 기본은 내 일정이고 스페이스를 바꾸면 내 일정으로 돌아간다.
  - 일간 목록은 `mine` 없이 받아 `assigneeId`로 거르고, 숨긴 일정이 있으면 "이 날 팀원 일정 N개는 숨겨져 있어요."와 팀 전체 보기를 안내한다. 주간·월간 점은 `mine` 파라미터를 보낸다. 참여자가 1명인 비개인 스페이스는 전환이 없으므로 `mine`을 보내지 않는다.
  - 이 구분은 서버 정의(`mine=true`는 담당자가 호출자)에 맞춘 것이다. 근거는 pinit-monolith `WorkspaceResourceService.java:72`(5bae2b24)이며 FE가 다시 정의하지 않는다.
  - 팀 전체에서 일정 카드는 제목 뒤 첫 항목에 담당자 이름(미정이면 "담당자 미정")을 보인다.
- 통계: report API는 선택 스페이스·프로젝트 범위를 더 보내지 않는다. 계획 비교의 주간 일정 조회는 `allSpaces`와 `mine`을 쓴다. 통계 화면에는 "모든 스페이스에서 내 기록이에요. 팀 기록은 스페이스에서 볼 수 있어요." 안내가 있다. 하루 계획(`planner`)은 여전히 선택 스페이스를 쓴다.
- 오늘의 작업 추가: 오늘 화면의 버튼은 `/app/tasks/new?from=today`로 간다. 이때 기본 소속이 `defaultSpaceId`(나의 스페이스)다. 스페이스 정보를 불러오는 중이라 값이 0이거나 `null`이면 기존 기본값(선택 스페이스)을 쓴다. 폼에서 바꿀 수 있다.

### 알려진 차이와 미해결 (커밋 6f42b6f 기준)

- 통계 보고서는 BE에서 아직 일정 `ownerId` 기준으로 센다. 확정 기준은 실제 실행한 사람이며 B단계 BE 계약 후 반영한다. 그때까지 내가 소유했지만 다른 사람이 담당인 일정은 계획 비교(담당자=나)와 보고서가 어긋날 수 있다.
- 일정 화면의 지연 일정 안내(`useOverdueSchedulesSummary`)는 `mine` 없이 조회하므로 내 일정 보기에서도 팀원의 지연 일정을 센다.
- 통계 화면의 컨텍스트 바는 통계가 전체 스페이스 기준인데도 선택된 스페이스의 목적을 보인다. 오늘·휴지통·마감 위험만 예외 처리돼 있다(`SpaceChrome.tsx`).

### B단계로 미룬 것

- 스페이스 허브(`/app/spaces`를 목록+개관으로 교체)와 요약 API(`/v2/spaces/summaries` 등).
- 내 통계 분해와 팀 기록(실행한 사람 기준 시간).
- 아직 결정하지 않은 개선(761–899px 스페이스 전환, 모바일 프로젝트 목록, 비활성 버튼의 불가 사유 등).
